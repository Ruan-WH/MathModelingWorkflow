# DrawIO 非数据图示

本 skill 不重跑模型，不重复 `3coding-visual` 的统计图。每次只为当前问题 i 生成确有论证价值的图示，不提前绘制后续问题。

## 选图

| 类型 | 文件名 | 使用条件 |
| --- | --- | --- |
| 总体路线图 | `fig_roadmap` | 展示已批准的全局框架，不泄露未完成问题的数值 |
| 求解流程图 | `fig_flow_qi` | 展示问题 i 的输入、处理、算法和输出 |
| 判断流程图 | `fig_decision_qi` | 存在阈值、可行性、收敛、异常或回退分支 |
| 数据流程图 | `fig_pipeline_qi` | 清洗、特征构造和模型输入有多步依赖 |
| 结构/关系图 | `fig_model_qi` | 模块、层次或变量关系用文字难以表达 |
| 指标体系图 | `fig_index_qi` | 存在目标层—准则层—指标层 |

判断流程图必须使用菱形判断节点，在分支线上写“是/否”“满足/不满足”或具体条件，并把失败路径连到真实的修正、回退或终止步骤。算法含“是否满足约束”“是否收敛”“候选解是否可行”时，优先画判断流程而非普通矩形串联。

## 强制视觉规范

- 只用黑白灰：背景 `#FFFFFF`，填充 `#FFFFFF/#F2F2F2`，文字与主边框 `#111111`，辅助线 `#666666`。禁止鲜艳色、渐变、阴影和装饰图标。
- 主节点边框与连接线 2–2.5 pt，分组框 1.5–2 pt；箭头清楚，不用发丝细线。
- 字体统一，并按论文最终插入尺寸验收。DrawIO 源图节点通常使用 16–18 pt，开始/结束节点可用 18–20 pt，分支标签不低于 14 pt；缩放插入论文后，节点正文的视觉字号不得低于论文图注字号，建议保持约 9–11 pt。文字限制 1–2 行，优先动宾短语。
- 整图只采用自上而下或自左向右一种主方向。
- 使用正交连接线并减少折点；线不得穿过节点，尽量不交叉。
- 紧凑排版：同级节点等宽等高并对齐；节点间距约 20–32 px，层级间距 28–45 px，外边距 16–24 px。
- 开始/结束用圆角矩形，处理用矩形，判断用菱形，输入输出用平行四边形。
- 图内不放大标题或长解释，交给 caption 与正文。

推荐样式：

```text
节点：fillColor=#FFFFFF;strokeColor=#111111;strokeWidth=2;fontColor=#111111;fontSize=17;
判断：rhombus;fillColor=#F2F2F2;strokeColor=#111111;strokeWidth=2;fontSize=17;
连线：edgeStyle=orthogonalEdgeStyle;rounded=0;strokeColor=#111111;strokeWidth=2;endArrow=block;endFill=1;
```

## 工作流

1. 读取当前问题的建模报告、结果报告和已有图清单。
2. 先列当前问题图示计划，删去不能增加理解的图。
3. 每图生成一个 `.drawio` 源文件。
4. 用 DrawIO CLI 以 crop 模式导出 PDF，并导出 PNG 预览。
5. 先检查独立 PNG 的重叠、交叉/穿越、分支标签、对齐、边距和黑白一致性，再按预计的 LaTeX 插图宽度嵌入论文并渲染整页。必须以正常整页阅读视图检查最终字号；若节点文字明显小于正文或图注，不得仅放大查看预览，应增大源图字号、缩短节点文字或适度增加论文插图宽度后重导。
6. 增量更新 `reports/DRAWIO_REPORT.md`，记录来源、用途、正文位置、导出和检查状态。

无法导出时保留源文件并记录准确原因，不得伪称完成视觉验收。当前图随问题 i 正文一同交付审查，用户批准前不画问题 i+1。
